# MOA 라이트 커뮤니티 워크스페이스 UI 개편 설계

## 목적

MOA의 로그인 후 전체 사용자 화면을 밝은 커뮤니티 워크스페이스 형태로 개편한다. 현재 화면을 둘러싼 큰 바깥 여백, 서로 맞지 않는 사이드바와 헤더 높이, 작은 내부 요소, 화면마다 다른 버튼·카드·입력창 스타일을 제거한다.

Discord와 Slack의 빠른 공간 전환과 일관된 앱 셸을 참고하되, 어두운 업무·게이밍 도구처럼 보이지 않도록 밝고 따뜻한 모임 서비스의 인상을 유지한다.

## 성공 기준

- 로그인 후 화면이 브라우저의 사용 가능한 영역을 자연스럽게 채운다.
- 모임 레일, 서비스 내비게이션, 상단 헤더의 높이와 경계선이 하나의 앱 셸처럼 연결된다.
- 검색, 카테고리, 목록, 상세, 폼, 후기, 마이페이지에서 같은 디자인 언어를 사용한다.
- 본문 글자, 카드, 입력창, 버튼과 클릭 영역이 현재보다 커지고 읽기 쉬워진다.
- 주요 라우트가 데스크톱, 태블릿, 모바일에서 기능 손실 없이 사용할 수 있다.
- 기존 API, 인증, 라우트, DTO와 상태 관리 동작은 유지된다.

## 비범위

- 백엔드 API 및 데이터 모델 변경
- 인증 방식, 쿠키 정책 또는 권한 체계 변경
- 라우트 URL 변경
- 새로운 서비스 기능 추가
- 공개 랜딩 페이지의 전면 재설계

## 디자인 방향

### 시각 언어

- 배경은 밝은 회색, 주요 콘텐츠 표면은 흰색으로 구성한다.
- 기본 텍스트는 진한 남청색, 보조 텍스트는 충분한 대비의 회색을 사용한다.
- MOA 주황색은 생성, 참여, 선택, 현재 위치처럼 의미 있는 행동과 상태에만 사용한다.
- 위험 색상은 삭제·탈퇴·모임 해체의 확인 단계에서만 강조한다.
- 카드 그림자는 얕게 유지하고, 화면 구조는 여백과 구분선으로 우선 표현한다.
- 애니메이션은 짧은 호버, 선택, 패널 전환에만 사용하며 반복 장식은 사용하지 않는다.

### 앱 셸

데스크톱 앱 셸은 다음 세 영역으로 구성한다.

1. **모임 레일**: 가입한 모임 전환과 모임 생성
2. **서비스 내비게이션**: 홈, 모임 찾기, 카테고리, 참여 일정, 관심 모임, 후기, 프로필
3. **콘텐츠 영역**: 통합 검색과 사용자 도구가 있는 상단 헤더 및 현재 라우트의 본문

상단 헤더는 서비스 내비게이션 상단과 같은 높이를 사용하고, 경계선을 연속적으로 연결한다. 콘텐츠 본문은 별도의 작은 중앙 카드에 가두지 않고 사용 가능한 너비를 활용한다. 단, 읽기 화면은 적절한 최대 본문 폭을 둔다.

모바일에서는 모임 전환을 하단 바에 배치하고, 서비스 내비게이션은 드로어로 전환한다. 콘텐츠는 한 열로 재배치하며 주요 행동은 화면에서 사라지지 않아야 한다.

## 공통 디자인 시스템

### 토큰

전역 토큰은 다음 범주를 제공한다.

- 배경, 표면, 경계선, 본문, 보조 텍스트, 브랜드, 위험 및 상태 색상
- 제목, 본문, 설명, 라벨의 글자 크기와 굵기
- 4px 기반 간격 체계
- 입력창, 버튼, 카드, 모달의 반경
- 표면 단계별 그림자
- 헤더, 레일, 모바일 내비게이션 크기
- 데스크톱, 태블릿, 모바일 브레이크포인트

### 공통 UI

기존 Emotion 구조와 함께 사용할 수 있는 재사용 UI 규칙 또는 컴포넌트를 만든다.

- Button: primary, secondary, ghost, destructive
- Input, Textarea, Select, SearchField
- Chip 및 선택·해제 가능한 FilterChip
- Card 및 모임 카드 구조
- PageHeader와 SectionHeader
- Modal 및 확인 대화상자
- Loading, Skeleton, EmptyState, ErrorState
- FormField와 필드 오류·도움말

화면별 스타일 파일은 공통 토큰과 UI를 소비한다. 전역 선택자로 기존 화면을 강제 덮어쓰는 방식은 사용하지 않는다.

## 화면별 설계

### 홈, 모임 목록, 검색 및 카테고리

- 상단에 명확한 페이지 제목과 설명을 제공한다.
- 검색은 헤더 통합 검색과 검색 페이지의 상세 검색을 같은 스타일로 연결한다.
- 카테고리 패널은 작은 부유 박스가 아니라 콘텐츠 영역 안에서 넓게 펼쳐진 필터 영역으로 제공한다.
- 선택된 조건은 해제 가능한 칩으로 표시한다.
- 모임 카드는 이미지, 카테고리·지역, 제목, 일정, 참여 정보, 상태 및 행동 순서를 일관되게 유지한다.
- 단기·정기 모임은 동일한 카드 체계를 공유하고 필요한 상태 정보만 달리 표시한다.

### 모임 상세, 생성 및 가입

- 상세 화면은 대표 이미지, 제목, 지역·일정·인원 및 참여 행동을 첫 화면에 배치한다.
- 소개, 일정, 멤버, 후기 등은 명확한 섹션으로 구분한다.
- 생성과 가입 폼은 동일한 FormField 구조와 입력 높이를 사용한다.
- 필수 여부, 도움말과 검증 오류는 해당 필드 가까이에 표시한다.
- 여러 단계로 이루어진 가입 과정은 현재 단계와 남은 단계를 명확히 표시한다.

### 후기, 공지 및 신고

- 읽기 중심 화면은 넓고 단순한 본문 레이아웃을 사용한다.
- 목록은 불필요한 중첩 카드 대신 구분선과 타이포 계층으로 정돈한다.
- 작성 화면은 공통 폼과 버튼 우선순위를 사용한다.
- 첨부 이미지와 긴 텍스트가 작은 화면에서도 넘치거나 잘리지 않아야 한다.

### 마이페이지와 참여 현황

- 데스크톱에서는 로컬 메뉴와 작업 영역을 나누고 모바일에서는 메뉴를 상단 선택기로 전환한다.
- 프로필 정보, 참여 모임, 작성 후기 및 계정 행동의 계층을 분리한다.
- 삭제와 탈퇴는 기본 화면에서 과도하게 강조하지 않고 확인 대화상자에서 결과를 분명히 설명한다.

### 모임 관리

코드의 `manager` 영역은 전역 관리자 콘솔이 아니라 모임장에게 제공되는 모임 관리 기능으로 취급한다. 일반 사용자 앱 셸 안에서 멤버, 통계, 투표, 제한 목록, 신고, 가입 승인 및 모임 정보 수정을 제공한다.

기존 가로 탭은 화면 폭에 맞는 관리 내비게이션으로 교체한다. 멤버 목록, 차트, 표와 행동 버튼은 공통 UI 및 상태 표현을 사용한다.

### 인증 화면

로그인, 회원가입, 아이디·비밀번호 찾기는 앱과 같은 브랜드 토큰을 사용한다. 앱 셸을 그대로 노출할 필요는 없지만 입력창, 버튼, 오류, 성공 메시지와 반응형 규칙은 공유한다.

## 데이터와 기능 경계

다음 기존 계층은 변경하지 않는다.

- API 엔드포인트 및 Axios 요청 구조
- 요청·응답 DTO
- 쿠키 기반 인증과 인증 만료 이벤트
- Zustand 스토어의 역할
- React Router 경로와 페이지 진입 조건

화면 컴포넌트는 기존 데이터와 이벤트 핸들러를 새 공통 UI에 연결한다. UI 개편 중 비즈니스 로직 문제를 발견해도 화면을 구현하는 데 필요한 최소 수정이 아니라면 별도 작업으로 분리한다.

## 상태와 오류 처리

- 최초 및 추가 로딩에는 레이아웃 이동을 줄이는 Skeleton 또는 정해진 로딩 영역을 사용한다.
- 결과가 없으면 페이지 문맥에 맞는 EmptyState와 다음 행동을 제공한다.
- API 오류는 사용자에게 이해 가능한 메시지와 가능한 경우 다시 시도 행동을 제공한다.
- 폼 검증 오류는 필드 단위로 표시하고 제출 실패 메시지는 폼 상단에도 요약한다.
- 모달은 키보드로 닫을 수 있고, 포커스가 모달 안에 유지되며, 닫힌 뒤 원래 요소로 돌아가야 한다.
- 삭제, 탈퇴, 추방, 모임 해체는 영향 범위를 설명하는 확인 단계를 거친다.

## 접근성과 반응형

- 텍스트와 배경은 충분한 색상 대비를 유지한다.
- 아이콘 전용 버튼에는 접근 가능한 이름을 제공한다.
- 모든 상호작용 요소는 키보드 포커스 상태가 보이게 한다.
- 기본 클릭·터치 영역은 모바일에서 최소 44px 수준을 확보한다.
- 720px 이하에서는 한 열 콘텐츠, 모바일 내비게이션 및 폭을 채우는 주요 입력을 사용한다.
- 긴 제목, 사용자 이름, 카테고리와 이미지가 레이아웃을 깨뜨리지 않아야 한다.

## 구현 순서

1. 전역 토큰과 공통 UI 요소
2. 앱 셸, 헤더, 모임 레일, 서비스 내비게이션과 모바일 내비게이션
3. 홈, 검색, 카테고리, 단기·정기 모임 목록
4. 모임 상세, 생성 및 가입 과정
5. 후기, 공지 및 신고
6. 마이페이지, 참여 현황 및 모임 관리
7. 로그인, 회원가입과 계정 찾기
8. 전 화면 반응형, 접근성 및 시각 회귀 정리

각 단계는 기존 기능을 사용할 수 있는 상태로 끝낸다. 공통 계층을 먼저 만들되 모든 화면을 한 번에 교체하는 전역 CSS 덮어쓰기는 피한다.

## 검증 전략

- `npm run build`로 TypeScript와 프로덕션 빌드를 검증한다.
- 기존 테스트가 있는 경우 실행하고 변경된 공통 UI에는 핵심 상태 테스트를 추가한다.
- 주요 라우트를 데스크톱, 태블릿, 모바일 크기로 확인한다.
- 검색, 카테고리 선택·해제, 모임 참여, 폼 오류, 모달, 빈 목록과 API 실패 상태를 확인한다.
- 키보드 탐색, 포커스 표시, 모달 포커스와 주요 색상 대비를 확인한다.
- 현재 작업 트리의 사용자 수정 사항을 보존하며, 겹치는 파일은 기존 변경 의도를 먼저 파악한 후 병합한다.

## 완료 조건

- 범위 내 모든 화면이 새 토큰과 공통 UI 규칙을 사용한다.
- 앱 셸과 내부 페이지 사이에 불연속적인 크기, 선 또는 바깥 여백이 없다.
- 버튼, 필드, 칩, 카드와 상태 표현이 화면마다 임의로 달라지지 않는다.
- 데스크톱과 모바일의 주요 사용자 흐름이 동작한다.
- 빌드와 관련 테스트가 통과하며 확인된 회귀가 없다.
