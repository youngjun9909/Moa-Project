# MOA 전체 사용자 페이지 디자인 통합 명세

## 목표

현재 개선된 카테고리 화면의 밝고 따뜻한 커뮤니티 무드를 기준으로 MOA의 모든 일반 사용자 화면을 재구성한다. 단순히 색상만 맞추지 않고 각 페이지의 정보 우선순위, 가독성, 여백, 동작 흐름을 목적에 맞게 정리한다.

완료된 화면은 다음 조건을 만족해야 한다.

- Discord·Slack처럼 구조가 명확하지만 더 밝고 친근한 모임 서비스 분위기다.
- 전역 헤더와 사이드바가 모든 앱 화면에서 자연스럽게 이어진다.
- 페이지마다 제목, 본문 폭, 카드 크기와 버튼 배치가 제각각이지 않다.
- 목록, 상세, 작성, 인증, 내 활동 화면은 각각 목적에 맞는 공통 패턴을 사용한다.
- 로딩, 오류, 데이터 없음 상태도 비어 보이는 문장 한 줄이 아니라 완성된 화면으로 표현한다.
- 데스크톱뿐 아니라 태블릿과 모바일에서도 정보 우선순위가 유지된다.

## 사용자와 권한 전제

- 모든 사용자는 일반 사용자다.
- 관리자 전용 시각 언어와 관리자 중심 메뉴는 일반 사용자 화면에 노출하지 않는다.
- 모임을 만든 사용자가 수행하는 참가자 확인, 모임 수정 같은 기능은 별도 관리자 시스템이 아니라 해당 모임의 운영 기능으로 표현한다.
- 기존 인증과 API 동작은 유지하되 화면 구조와 명칭은 일반 사용자의 관점으로 정리한다.

## 디자인 방향

### 색상과 표면

- 기존 전역 배경색은 유지한다.
- 주요 행동은 코랄 계열을 사용한다.
- 보조 선택 요소는 따뜻한 크림색 칩을 사용한다.
- 흰색 표면, 얇은 중성 테두리, 약한 그림자로 영역을 구분한다.
- 회색으로 채운 무거운 버튼은 사용하지 않는다.
- 삭제, 탈퇴, 신고처럼 위험한 행동만 별도의 경고 색상을 사용한다.

### 크기와 간격

- 전역 헤더 높이는 64px을 유지한다.
- 일반 페이지 본문은 최대 1320~1440px 범위로 통일한다.
- 페이지 좌우 여백은 데스크톱 24~56px, 모바일 12~20px 범위를 사용한다.
- 기본 버튼 높이는 40~44px, 입력 필드는 44~48px을 사용한다.
- 카드 모서리, 칩, 입력 필드의 반경은 공통 토큰을 사용한다.

### 타이포그래피

- 각 페이지에는 하나의 명확한 H1만 둔다.
- 페이지 설명, 결과 개수, 보조 메타데이터의 위계를 구분한다.
- 오래된 작은 글자와 장식용 구분선 문자열은 제거한다.
- 긴 제목과 주소는 줄임 처리를 하되 상세 화면에서는 전체 내용을 제공한다.

## 공통 화면 패턴

### 1. 모임 목록 화면

대상: 홈, 단기 모임, 정기 모임, 카테고리 결과, 키워드 검색, 관심 모임.

- `PageHeader`: 영문 또는 짧은 눈썹 문구, 제목, 설명, 필요 시 행동 버튼.
- `MeetingTypeTabs`: 전체·단기·정기 전환. 현재 항목을 명확하게 강조한다.
- `ResultToolbar`: 목록 제목, 결과 개수, 선택 조건, 정렬 버튼.
- `MeetingGrid`: 데스크톱 4열, 중간 화면 3열·2열, 모바일 1열.
- 페이지당 12개와 숫자 페이지네이션을 기본으로 한다.
- 모든 모임 카드는 동일한 이미지 비율과 높이를 사용한다.
- 카드에는 카테고리, 제목, 날짜, 지역, 관심 버튼을 일관된 순서로 배치한다.
- 로딩은 스피너 또는 스켈레톤, 빈 결과는 아이콘·설명·복구 행동이 있는 카드로 표시한다.

단기·정기 모임은 별도 디자인을 만들지 않고 같은 목록 셸에 타입과 설명만 바꿔 사용한다.

### 2. 모임 상세 및 참여 흐름

대상: 모임 상세, 참여 시작, 참여 답변, 참여 결과, 참여자 목록.

- 상단에 대표 이미지와 핵심 정보를 배치한다.
- 카테고리, 모임 유형, 날짜, 장소는 빠르게 읽을 수 있는 메타 영역으로 묶는다.
- 소개, 준비물, 참여 질문은 구분된 섹션 카드로 표현한다.
- 참여·관심·신고 같은 행동의 우선순위를 색상과 위치로 구분한다.
- 참여 과정은 단계 표시를 사용하고 이전·다음 버튼 위치를 일관되게 유지한다.
- 모임 운영 기능은 일반 사용자 내 모임 관리 도구로 표현한다.

### 3. 작성 및 편집 화면

대상: 모임 생성, 모임 수정, 후기 작성, 신고, 회원정보 수정.

- 현재 모임 생성 화면의 넓은 작업 영역과 단계형 구성을 기준으로 한다.
- 관련 필드를 의미 단위로 묶고 레이블, 도움말, 오류 문구를 입력 요소 가까이에 둔다.
- 이미지 업로드는 미리보기와 교체·삭제 동작을 명확하게 제공한다.
- 이전·취소는 보조 버튼, 다음·저장·완료는 주요 버튼으로 통일한다.
- 긴 양식은 한 장에 몰아넣지 않고 단계 또는 섹션으로 분리한다.

### 4. 사용자 활동 화면

대상: 참여 일정, 내 후기, 마이페이지 시작, 회원정보 조회, 회원 탈퇴.

- 사용자 상태를 요약하는 페이지 헤더와 핵심 정보 카드를 사용한다.
- 목록이 있는 화면은 공통 툴바와 카드 또는 테이블 패턴을 사용한다.
- 회원 탈퇴는 일반 설정과 시각적으로 분리된 위험 영역으로 둔다.
- 인증이 필요한 경로는 기존 리디렉션을 유지한다.

### 5. 커뮤니티 콘텐츠 화면

대상: 후기 게시판, 공지사항.

- 후기 게시판은 이미지, 모임명, 작성자, 날짜, 내용이 읽기 좋은 피드 카드로 구성한다.
- 후기 작성 버튼은 페이지 헤더의 주요 행동으로 둔다.
- 공지사항은 카드 나열 대신 날짜와 제목을 빠르게 훑을 수 있는 목록 구조를 사용한다.
- 각 화면에 로딩, 빈 상태와 오류 상태를 제공한다.

### 6. 인증 화면

대상: 로그인, 회원가입, 아이디 찾기, 비밀번호 찾기·재설정, SNS 인증 결과.

- 현재 개선된 로그인 카드의 폭, 여백, 색상과 타이포그래피를 기준으로 한다.
- 회원가입처럼 긴 화면은 섹션 또는 단계로 분리한다.
- 성공, 오류, 확인 상태는 같은 피드백 패턴을 사용한다.
- 인증 화면에서는 앱 사이드바와 전역 헤더를 노출하지 않는다.

### 7. 소개 랜딩 화면

대상: 루트 웹 메인.

- 앱 화면과 같은 브랜드 토큰을 사용한다.
- 서비스 소개, 핵심 가치, 인기 활동, 시작 행동을 명확한 순서로 배치한다.
- 앱으로 진입하는 행동과 로그인 행동을 구분한다.

## 구현 구조

중복 화면을 페이지별 CSS로 다시 꾸미지 않고 다음 공통 구성요소를 만든다.

- `PageHeader`
- `SectionCard`
- `MeetingListPage`
- `MeetingCard`
- `ResultToolbar`
- `SortTabs`
- `Pagination`
- `LoadingState`
- `EmptyState`
- `ErrorState`
- `FormSection`
- `FormActions`
- `DangerZone`

기존 기능 컴포넌트는 데이터 요청과 사용자 동작을 담당하고, 공통 구성요소는 화면 표현을 담당한다. 단기·정기 모임처럼 거의 같은 화면은 하나의 구성요소에 타입을 전달하여 중복 코드를 제거한다.

## 데이터와 상태

- 목록 API는 페이지당 12개를 기본으로 요청한다.
- 정렬 또는 필터가 바뀌면 첫 페이지로 돌아간다.
- 필터를 선택하지 않으면 전체 목록을 조회한다.
- 키워드 검색은 헤더 검색창만 사용한다.
- 비어 있는 결과와 요청 오류를 구분해서 표시한다.
- 기존 관심 모임, 인증, 이미지 URL 규칙은 유지한다.
- 무한 스크롤이 정보 탐색에 불리한 후기·목록 화면은 페이지네이션 또는 명확한 더 보기 방식으로 통일한다.

## 반응형 기준

- 1120px 이하: 4열 목록을 3열로 변경한다.
- 820px 이하: 2열로 변경하고 헤더 행동 영역을 줄바꿈한다.
- 720px 이하: 사이드바를 모바일 메뉴로 전환하고 폼·필터를 한 열로 배치한다.
- 520px 이하: 모임 카드를 1열로 배치한다.
- 고정 픽셀 너비와 과도한 최소 너비를 제거하여 가로 스크롤을 방지한다.

## 접근성과 상호작용

- 아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다.
- 클릭 가능한 이미지는 버튼 또는 링크 의미를 갖도록 한다.
- 선택형 칩은 `aria-pressed`, 현재 페이지는 `aria-current`를 사용한다.
- 키보드 초점 스타일을 유지한다.
- 로딩과 오류 메시지는 보조 기술에서도 읽을 수 있게 표현한다.
- 위험 행동에는 명확한 확인 단계를 제공한다.

## 테스트 및 검수

- 공통 구성요소의 렌더링과 변형을 단위 테스트한다.
- 목록 필터, 정렬, 페이지 변경, 빈 상태 복구 행동을 테스트한다.
- 인증이 필요한 경로의 리디렉션을 유지하는지 확인한다.
- 프론트 전체 테스트와 프로덕션 빌드를 실행한다.
- 백엔드 조회 변경이 포함된 경우 백엔드 전체 테스트도 실행한다.
- 데스크톱과 모바일 폭에서 모든 활성 사용자 경로를 실제 브라우저로 순회한다.
- 화면마다 제목, 본문 폭, 주요 행동, 로딩, 빈 상태, 오류 상태를 확인한다.

## 완료 기준

- 활성 사용자 경로에서 기존의 작은 중앙 폼, 과도한 공백, 텍스트 구분선 정렬 메뉴, 불균일한 카드, 회색 기본 버튼이 남아 있지 않다.
- 각 화면은 동일한 MOA 서비스로 보이면서도 해당 작업 목적에 맞는 배치를 갖는다.
- 단기·정기 모임을 포함한 모든 목록 화면이 공통 카드와 툴바를 사용한다.
- 모든 테스트와 빌드가 성공한다.
- 실제 브라우저 검수에서 레이아웃 잘림과 가로 스크롤이 없다.
